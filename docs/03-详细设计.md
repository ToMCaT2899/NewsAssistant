# 详细设计

2026-11-23 增量：新增 GET/POST `/api/v1/chat/sessions` 与
GET/POST `/api/v1/chat/sessions/{id}/turns`，沿用 Bearer 鉴权，写轮次要求 Idempotency-Key。
worker 执行聊天；生成模式关联版本化任务；GET 返回最新工具状态、回答、简报及投递结果。
实现规则见 [ADR 0004](adr/0004-聊天与简报版本.md)；原设计中的每日唯一仅指 edition=0 正式版。

## 1. 服务边界与接口
下列是已实现的 v1 API 契约；完整外部服务联调仍待验证。另提供 GET /runs 分页列表与 GET /status 配置状态。
统一前缀 /api/v1，除健康检查和登录外需 Bearer token。MVP 使用管理员预置账号；
密码仅存哈希，登录使用成熟哈希库和签名 token，不自行设计加密。收件邮箱修改需重新验证；
验证流程未实现前仅允许管理员配置已验证收件地址，禁止开放匿名邮件发送。

- POST /auth/login：账号与密码换取短期 token；认证失败返回 401，限速。
- GET /subscription：只读取当前用户订阅。
- PUT /subscription：完整更新配置，包含 version；版本冲突返回 409。
- POST /runs：以 Idempotency-Key 创建任务；返回 202 和 run_id，已完成则返回已有资源。
- GET /runs/{id}：返回状态、预算计数、错误类别和简报 ID；不返回密钥或原始提示词。
- GET /runs/{id}/tool-calls：分页查看脱敏工具记录；归属不匹配返回 404。
- GET /briefs：按当前用户分页，page_size 默认 20、上限 100。
- GET /briefs/{id}：简报、条目、来源和邮件状态。
- POST /deliveries/{id}/retry：仅允许 failed；unknown 返回 409，需先核查并明确确认重复风险。
- GET /health：进程存活；就绪检查另外报告数据库与配置状态，不向匿名用户披露配置。

响应错误：error.code、error.message、request_id；字段校验返回 422。
创建任务返回 run_id、status、reused、brief_id。身份和 subscription_id 从鉴权上下文读取，
不得相信模型或请求体提供的任意 user_id。业务异常映射稳定错误码，禁止返回内部堆栈。

订阅输入：persona 1..200 字；topics 最多 10 个；include/exclude_keywords 各最多 20 个，
每项最多 50 字；max_items 1..10；lookback_hours 1..72；local_send_time 为 HH:MM；
timezone 为有效 IANA 名称；recipient_email 为已验证地址；enabled 为布尔值。
条件词冲突时排除词优先。默认 max_items=5、lookback_hours=24、local_send_time=08:00、
timezone=Asia/Shanghai。以上为可调整的 MVP 产品决策。

## 容器与配置约定
使用 Docker Compose，目标由 api、worker、frontend、migrate 组成；当前已提供业务服务及 tools profile 下的 check/db-init。
api/worker 共享 /app/data 命名卷，worker 单独挂载 /app/workspace；SQLite URL 使用绝对路径。
迁移任务成功后启动业务服务；当前 db-init 只适用于新库，不能作为每次启动钩子。
.env 只留在宿主机，通过 Compose environment 按服务显式注入配置；前端不接触密钥。
已提供健康检查、停止宽限期与运行时恢复。容器重启不清理持久化任务状态。
详见[Docker Compose 运行说明](07-Docker-Compose运行说明.md)。

## 2. 创建任务与调度
独立 worker 每 30 秒扫描 enabled 且 next_run_at <= now 的订阅。
在短事务内尝试插入 run，scheduled 的 idempotency_key 固定为 daily:本地业务日期；
随后以版本条件推进 next_run_at；日幂等键保护两个短事务间的重扫。UNIQUE(subscription_id, idempotency_key) 防止重复扫描建任务。
手动调用使用 manual:客户端幂等键，键长度和有效期由 API 校验；先复用当日正式简报，
再检查该订阅是否已有 queued/running 的 run，避免并发生成。

MVP 错过执行时间时，只补当前本地日期最近一次到期任务，不连续补发历史日期。
夏令时不存在的时刻取该日之后第一个有效时刻；重复时刻只执行一次，业务日期唯一键兜底。
worker 用条件 UPDATE 将 queued 改成 running，受影响行数为 1 才算领取成功。
运行期间按 lease 更新；生成任务过期标记 incomplete，重新生成需新 run 和 attempt_key；
不假设只靠 LangGraph checkpointer 就能恢复外部操作。
每个任务冻结订阅快照、window_end=触发时刻、window_start=end-lookback_hours。

## 3. Agent 状态和图
RunState 包含 messages（追加 reducer）、run_id、subscription_snapshot、window_start/end、
business_date、seen_article_ids、model_calls、tool_calls、deadline、draft、validation_errors。
user_id 和 workspace 根目录由可信运行上下文注入，不作为模型可自由填写参数。

图：START → budget_guard → agent → route。
route 根据模型结果选择 tools 或 validate；tools → budget_guard；
validate 通过则 END，否则附上结构化反馈 → budget_guard。
budget_guard 超限终止为 incomplete；不可恢复模型错误终止为 failed。
即便模型无工具调用，也必须进入 validate，不把任意文本直接当正式简报。
代码只固定此调度机制，不预先固定搜索关键词、来源、工具顺序或次数。

模型输入由系统规则、冻结订阅、时间范围、历史摘要、工具 schema、近期 observation 组成。
工具 schema 包括参数类型、用途、结果格式和副作用说明。结果使用 tool_call_id 与请求配对。
模型返回未知工具、非法参数时生成对应错误 observation，不能丢失调用配对。
默认串行执行工具；将来允许并行读取时仍须一次性预留批次预算，写文件不得无序并发。

预算初值：最多 15 次模型请求、20 次工具调用、总计 180 秒。
模型请求失败重试也计数；校验修正不重置预算；时间截止用单调时钟。
工具的失败、拒绝也计入尝试次数；预留本批后再执行，剩余不足时为每个未执行调用返回错误，
随后终止任务。LLM 请求 timeout 不得超过剩余总时长，重试在预算内最多 2 次。
不承诺所有供应商支持取消；deadline 后迟到结果不得触发发布。
LangGraph recursion_limit 另设防护，不能当作精确模型或工具调用计数。

## 4. 工具契约
所有工具返回统一 envelope：ok、data、error{code,retryable,message}、truncated。
结果大小受限，工具执行记录保存摘要和裁剪后的参数，不无限保存正文到消息历史。

基础五工具：
- list_dir(path)：仅列本次运行目录，最多 100 项。
- read_file(path)：仅读取该目录文本，最多 64 KiB。
- search_content(keyword, dir)：字面关键词搜索，最多 100 个结果，不执行正则。
- write_file(path, content)：限制目录、单文件 64 KiB、目录配额；原子替换，禁止写项目配置。
- bash(command)：保留题目接口，默认关闭；关闭时返回 TOOL_DISABLED。
  开启时只接受严格白名单命令，经解析映射到固定可执行文件 argv，以 shell=False 运行；
  不传递给 bash -c、cmd /c 或 PowerShell，禁止操作符、重定向、命令替换和用户指定程序。
  不继承密钥环境变量，设置 cwd、超时、输出上限；需要真正任意 shell 时另行采用 OS 沙箱。
  验收启用受控演示模式，证明允许命令可执行且越权命令被拒绝，不能仅以禁用状态宣称完成。

新闻工具：
- search_news(query, start_time, end_time, limit=10)：limit 上限 20；
  时间不得超出任务窗口；返回 article_id、标题、URL、来源、发布时间及可用摘录。
- fetch_feed(source_id)：仅接受管理员配置的来源，返回窗口内条目与规范化 article_id。
- fetch_article(article_id)：从已经登记的 URL 读取，返回正文、抓取时间、内容哈希与证据级别。
- get_recent_briefs(days=7)：仅当前用户，最多 30 天，返回已推送事件摘要与链接。

文件路径 resolve 后须在 workspace/run_id 之内，拒绝绝对路径、.. 越界和 symlink/reparse
逃逸；工具不接触仓库根目录、.env、数据库及其他用户目录。
URL 仅允许 http/https，阻止私有、loopback、link-local、保留地址、元数据与非允许端口；
DNS 解析及每次跳转均重新校验，连接目标须绑定已校验地址，防 DNS rebinding。
抓取最多 2 MiB、提取正文最多 30,000 字符、timeout=15 秒，限制解压后的大小。
搜索结果中的任何指令只作为数据；来源不能要求发送邮件、读密钥或扩大工具权限。

## 5. 新闻整理与输出校验
程序负责 URL 规范化与精确去重；LLM 负责同事件合并、相关度判断、摘要和推荐理由。
URL 规范化仅移除已知跟踪参数和 fragment，不删除语义参数；保留原始 URL。
同事件多来源可关联同一条目，保留原始发布者优先，转载不作为独立新闻堆叠。

草稿字段：title、overview、coverage(start/end)、no_news、items。
item 字段：headline、summary、why_it_matters、event_key、sources[{article_id,evidence_level}]。
evidence_level 为 full_text 或 search_excerpt，摘录证据必须明确标注。
模型输出只引用 article_id，渲染时由数据库取真实 URL，避免虚构链接。
校验：条数上限、字段长度、引用存在且本次可见、来源非空、重复 event_key、来源时间窗口。
发布时间未知的内容默认不入每日新闻；如用于背景解释，必须单独标记，不能当作当天事件。
no_news=true 必须 items=[] 并说明检索范围；正常简报至少 1 条。
程序只能校验引用与结构，不能据此声称证明事实绝对真实。重要冲突需模型查看原始来源，
无法核实时删除条目或明确说明。最多 2 次格式修正，并继续计入原预算。

## 6. 发布与事务
短事务内复核当前订阅状态及已验证邮箱，写 brief、items、sources、delivery 后提交。
briefs 的 UNIQUE(subscription_id,business_date) 是最终幂等边界；
并发冲突时事务回滚，读取已有简报，不能覆盖已发送内容。run 仍可标记 succeeded 并引用复用结果。
发布前确认 deadline 与 run 领取状态；过期 worker 不能发布。
不完整草稿存在 runs.draft_json，不能混入正式简报或自动 outbox。

## 7. QQ 邮箱发送
应用管理员在 QQ 邮箱开启 SMTP 并获取授权码；统一发件账号配置在环境变量：
SMTP_HOST=smtp.qq.com、SMTP_PORT=465、SMTP_USE_SSL=true、SMTP_USERNAME、SMTP_AUTH_CODE。
SMTP_AUTH_CODE 是授权码，不是 QQ 登录密码；启动时校验必填配置，缺少则邮件通道不可用。
使用 TLS 证书校验，HTML 自动转义，链接仅 http/https，清理邮件头换行并提供纯文本版本。
主题示例：[AI 日报] 2026-11-22；日期取 brief.business_date。
每个 delivery 预先生成稳定 Message-ID，仅用于追踪，不作为 SMTP 去重承诺。

发送步骤：
1. 在短事务内条件领取 pending/retry_wait 且到期记录，改 sending、增加 attempt_count，
   记录 delivery_attempt 和 lease；只在领取成功后连接 SMTP。
2. 网络发送不持有数据库事务。最终 DATA 回复接受后写 accepted。
3. 明确未提交的连接失败、明确临时拒绝才允许 60/300 秒退避，含首次最多 3 次。
4. 永久拒绝、认证或配置错误写 failed，不自动重试；日志脱敏。
5. DATA 已提交后超时、回复丢失、进程崩溃或接受后写库失败，结果为 unknown，
   过期 sending 同样恢复为 unknown，禁止自动重发。
6. unknown 需人工检查发件记录并确认后才可重发；重新发送会增加重复风险，
   记录确认者和原因。客户端不能随意将 unknown 改为 failed 绕过限制。

accepted 仅代表 SMTP 接受，不代表已投递、未进垃圾箱或已阅读。
修改邮箱不会改变历史发送目标；关闭订阅取消 pending/retry_wait，sending 无法保证撤回。

## 8. 日志与保留
关联 request_id、run_id、tool_call_id、delivery_id，记录状态、计数、时延和错误类别。
密钥、完整邮箱、密码、全文及原始模型上下文默认不写日志；工具参数按字段过滤。
正文 30 天、工具摘要 14 天、正式简报 180 天为规划默认值；当前尚未启用自动清理。
部署者需安排备份和容量管理，不能把规划天数当作已经执行的保留策略。
删除正文保留文章元数据、来源链接和引用关系；清理不得产生外键悬空。
普通用户仅看自己的任务与简报；运维凭证和原始基础设施错误不得暴露给前端。
