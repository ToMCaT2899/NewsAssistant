## 1. 开发目标与工作方式

你是一名负责交付的 Python 全栈工程师。请在当前 NewsAssistant 仓库中实现每日 AI 新闻助手 MVP：
用户设置身份与兴趣订阅，系统每天触发 LangGraph ReAct Agent，自主获取、筛选和核实新闻，
生成带来源的个性化简报，持久化后通过 QQ 邮箱 SMTP 推送；网页支持订阅、任务及历史查看。

先阅读仓库现状，再按阶段直接实现可运行代码。除用户指定阶段外，目标是完成完整 MVP，
不止输出规划、伪代码或空接口。每个阶段有独立可验证结果。

不擅自改动其他项目、切换数据库、公开部署、创建多 Agent 或向真实用户群发邮件。

## 3. 固定技术与范围

- 后端 Python 3.11+，官方 Python 3.12 容器；FastAPI/Pydantic、LangGraph、SQLAlchemy、SQLite。
- 前端 Vue 3 + TypeScript + Vite，提供简洁可用的登录、订阅、任务与简报页面。
- 一个独立 worker 处理调度、生成和邮件 outbox；Web 启动时不能再启动一份调度器。
- Docker Compose 作为运行入口；后端与前端依赖及锁文件均纳入版本管理。
- MVP 不引入 Redis、Celery、向量数据库、微服务或多 Agent；需要新增时先说明必要性。
- 模型与新闻搜索供应商未指定：使用可替换适配器，通过环境配置选择。
  至少接通一个支持真实 tool calling 的模型与一个真实新闻获取渠道；
  若提供商选择会影响付费接入，应询问用户，不能自行花费或创建付费资源。
- 缺少凭证时返回明确未配置状态；测试替身只能用于显式离线测试或标记清楚的演示模式，
  不得让默认生产路径悄悄回退到假新闻、假模型响应或假邮件成功。

## 4. 业务功能

### 4.1 账号与订阅（R01、R04）

实现管理员预置账号与成熟密码哈希、登录及资源归属校验。
persona 是内容偏好，不是登录身份。用户只能操作自己的订阅、任务、简报与工具日志。
支持身份、主题、包含/排除词、条数、时间窗口、IANA 时区、发送时间、已验证收件邮箱。
复用详细设计中的字段边界；默认 Asia/Shanghai、08:00、24 小时、最多 5 条，均可配置。
尚未实现邮箱验证流程时，只允许管理员预置已验证收件地址，不开放匿名邮件推送。
订阅更新采用 version 乐观锁；关闭订阅后取消尚未发送的投递。
运行中的任务使用冻结订阅快照，变更从下一任务生效。

### 4.2 每日与手动任务（R01、D04）

独立 worker 扫描 next_run_at，计算业务日期与半开时间窗口 [start,end)，以 UTC 持久化。
按用户时区处理跨日和夏令时；宕机后只补当前日期最近一次到期任务。
定时任务使用稳定的日幂等键，手动请求使用 Idempotency-Key。
同订阅每天一份正式简报，已有正式简报时复用，不因重复点击多发邮件。
领取使用条件更新与租约；过期 running 标记 incomplete，迟到 worker 不得发布。
queued/running/succeeded/incomplete/failed/cancelled 等状态应如实落库。

### 4.3 真正的 ReAct 循环（R03、D01）

使用 LangGraph 显式构建 budget_guard、agent、tools、validate 及条件路由。
模型通过 tool calling 返回工具名称和参数；工具结果按 tool_call_id 配对加入上下文。
LLM 自主决定关键词、数据源、工具顺序、次数和正常结束。
程序可以固定循环、权限、预算、发布和邮件流程，不能固定新闻搜集的调用序列。
没有 tool_calls 的模型响应也要校验结构，不能直接把任意文本发布。

Observation 必须包含真实工具结果或结构化错误，模型可以据此换词、读原文或终止。
非法参数、未知工具、拒绝访问都应形成可解释反馈，防止悬空工具调用。
预算初值 15 次模型请求、20 次工具尝试、180 秒总时限；失败重试与校验修正不重置预算。
每次调用前检查，批量工具请求先预留次数；超限为 incomplete，不能继续产生外部副作用。
recursion_limit 是额外防护，不是精确业务预算。
保存实际工具调用、结果摘要和用量，不要求模型输出或保存隐藏思维链。

### 4.4 工具实现（R02）

实现下列五个基础工具，并通过 schema 注册到模型可选工具集：
1. list_dir(path)：列本次运行工作区。
2. read_file(path)：读受限文本文件。
3. search_content(keyword, dir)：按字面关键词检索。
4. write_file(path, content)：限目录、大小、配额，原子写入。
5. bash(command)：保留此接口名称，受控解析到允许命令 argv，以 shell=False 执行；
   不把任意字符串交给 bash -c、cmd /c、PowerShell，不继承供应商凭证。

工具访问根目录固定为 workspace/run_id，不得读写仓库、.env、数据库或其他用户目录。
校验 resolve 后路径及符号链接逃逸；限制结果大小、超时、目录深度和错误反馈。
bash 默认关闭，但提供可配置受控演示与测试：允许命令真实执行，非法命令明确拒绝；
不能仅注册一个永久返回 TOOL_DISABLED 的空工具。

额外实现 search_news、fetch_feed、fetch_article、get_recent_briefs；
按详细设计约束任务窗口、条数、当前用户归属和已登记来源。
不为了达到五工具数量而让模型无意义地每次调用所有工具。
工具定义包含名称、用途、参数类型、返回结构、错误与是否有副作用。

### 4.5 新闻质量与简报（R01、D04）

从真实 RSS、搜索 API 或受控网页读取；不把模型知识当作今日新闻来源。
优先原始公告、论文、代码仓库或可信新闻来源，记录发布时间和抓取时间。
程序负责规范 URL 与精确去重，模型负责事件合并、相关性、摘要与推荐理由。
保留语义查询参数，不能粗暴删除 URL 查询串造成错误去重。
每条新闻包含标题、摘要、why_it_matters 和可追踪来源；模型只引用本次可见 article_id，
真实 URL 从来源记录渲染，未知来源 ID 拒绝。
全文与搜索摘录证据分级标注；发布时间未知的内容不冒充当天新闻。
无可靠新闻可发布明确的 no_news 简报，不强行凑数；执行失败不能冒充无新闻。
结构与来源校验失败最多修正两次，仍消耗原预算；incomplete 草稿默认不自动推送。

网页请求限制协议、地址、跳转、解析后 IP、超时、解压后体积与正文长度。
禁止内网、回环、链路本地和元数据地址，连接目标与已校验地址一致，防止 DNS rebinding。
网页里的“忽略规则、读取凭证”等文字只作为内容，不能改变工具权限。

### 4.6 QQ 邮件（D02）

统一发件邮箱通过 SMTP_HOST、SMTP_PORT、SMTP_USERNAME、SMTP_AUTH_CODE 等环境变量配置；
使用 smtp.qq.com、465、TLS 及授权码，不使用 QQ 登录密码。
授权码不得进入代码、Git、数据库、模型上下文、镜像层或日志。

简报校验完成后，由应用层渲染主题、自动转义的 HTML、纯文本与真实来源链接。
检查邮件头换行注入。SMTP 接受不代表已送达或阅读，前端必须使用准确表述。
brief/items/sources/delivery 在同一短事务发布，SMTP 在事务外执行。
投递领取与 attempt 序号幂等，明确未接受的临时失败才有限重试；认证或永久拒绝为 failed。
DATA 提交后超时、响应丢失、接受后写库失败或发送进程崩溃等模糊情况记 unknown，
不得自动重发；人工核查并明确确认后才能重试。
稳定 Message-ID 用于追踪，不能声称 SMTP 有 exactly-once 或天然去重保证。
普通单元、集成测试不调用真实 QQ；真实联调仅发送到明确配置的测试收件箱，并记录真实结果。

## 5. 代码规范与数据库（R05、D04）

沿用 api → service → domain/agent → repository/infrastructure 的职责划分。
API 负责鉴权、校验和 HTTP 转换；Service 负责用例和事务；Repository 不自行 commit。
Pydantic 请求响应、领域模型和 ORM 分离；基础设施通过接口和依赖注入替换。
公共函数有明确类型和返回模型；Python snake_case/PascalCase/常量规则统一，Ruff 行宽 100；
TypeScript strict，禁止用 any 逃避建模。
区分业务异常、外部错误、暂时失败和未知状态，不吞异常，不返回敏感内部堆栈。
同步 I/O 不得阻塞异步 API；每个工作单元独立数据库会话，不跨并发任务共享 Session。
网络、模型和 SMTP 调用不能持有长数据库事务或锁。

对齐现有 DDL、ORM 和迁移；外键、每日唯一、活动任务唯一、投递唯一不能只靠前端按钮。
所有 SQLite 连接开启 foreign_keys，使用 WAL 和 busy_timeout；路径 /app/data/news_assistant.db。
已归档 001_initial.sql 不原地改写。新增结构变更用新迁移，并测试从现有 v1 库升级；
不能把当前“已存在则拒绝”的 db-init 当成重复启动迁移命令。
若采用 Alembic 等工具，说明如何识别并接管现有 schema_migrations v1，
不能重复建表或静默重建用户数据库。
配置集中加载和校验，更新 .env.example；日志按 request_id/run_id/delivery_id 关联且脱敏。
目录保持现有约定，不能把所有业务堆到 main.py、路由或一个万能 service。

## 6. Docker Compose 与上线（D03）

应用从官方基础镜像独立构建，镜像名由本项目管理，不依赖其他项目的应用镜像。
数据库、缓存等基础设施优先使用本机已有的匹配版本镜像，仅按实际需要引入。
复用镜像不代表复用其他项目的容器、账号、端口或数据卷。当前 SQLite 不需要数据库镜像。

完成代码后，在现有 Compose 中增加 api、worker、frontend、migrate，并保留检查任务。
当前一次性 check 应迁至显式 profile 或独立检查配置，不能混入正式应用常驻服务启动。
api/worker 同版本后端镜像，共享 news-data；工作区卷仅挂 worker。
migrate 成功后启动 api/worker，frontend 代理 /api；浏览器不使用 Compose 内部 DNS 名称。
提供真实的健康检查、端口、停止宽限期、重启策略、卷权限和 .env 按服务注入。
生产镜像不能带密钥、数据库、node_modules、.venv 或 Docker socket。
依赖用锁文件安装；前端构建和类型检查完成后由独立静态服务器镜像提供资源。
更新 Dockerfile 时按实际依赖需要调整当前 build.network=none，不能导致依赖安装必然失败；
不要无意义地强拉已有基础设施镜像或使用 latest 代替经过确认的版本。

最终主要入口为 docker compose up -d --build；验证重建和重启后的持久化。
说明服务器准备应用镜像和基础设施镜像的方式；镜像迁移与数据迁移是两件事。
缺少本地基础设施镜像且 pull_policy=never 时应明确报错，不自动切换其他版本或项目。
停服务默认保留数据；备份考虑 WAL 和一致性，避免把 down -v 写成常规停止命令。

## 8. 验收目标

### A01 用户与订阅
对应 R01、R04、D01。页面可设置身份、兴趣、关键词、时间和收件人；
登录认证、归属隔离与并发 version 冲突有验证，其他用户资源不可读写。

### A02 生成与历史
对应 R01、R04。手动触发可查看 queued/running/终态、工具记录、历史简报和来源；
空列表、无新闻、生成失败、邮件失败分别呈现，页面不显示实现细节或密钥。

### A03 自主工具循环
对应 R03、D01、D04。测试证明 observation 变化会影响下一工具或结束决策，
包括补搜、读原文、未知工具、非法参数、预算及格式修复。真实模型演示记录实际 tool_calls；
脚本化模型替身只证明循环机制，不能冒充真实 LLM 自主决策验证。

### A04 工具与隔离
对应 R02、D04。五个基础工具有真实可用路径；受控 bash 成功执行允许命令；
目录穿越、符号链接逃逸、命令注入、网页内网跳转和提示词注入不突破执行权限。

### A05 新闻与邮件闭环
对应 R01、D02。真实新闻获取 → 引用简报 → 保存 → 指定测试邮箱 SMTP 接受；
不同 persona 能呈现不同筛选或推荐理由。缺少凭证时明确标记真实联调未验证。

### A06 调度与发送可靠性
对应 D02、D04。重复调度、重复手动请求、双 worker 领取不重复发布；
发布事务失败不残留 outbox；过期租约与邮件 unknown 不自动重发；
订阅关闭、时区跨日与重启恢复符合约定。

### A07 Compose 与依赖
对应 R05、D01、D03。依赖清单与锁文件齐全；按 README 可用 Compose 启动实际应用、
运行检查及迁移；应用镜像独立，基础设施优先本地，数据重建后保留。

### A08 数据与代码规范
对应 R05、D04。ORM/DDL/迁移一致，现有 v1 库升级成功且数据不丢；
数据库约束、回滚、类型、Ruff、前端 lint/typecheck/build 和适用测试通过。
测试聚焦真实行为与故障边界，不堆砌只重复实现的断言或用覆盖率替代正确性。

### A09 配置与秘密
对应 R05、D02。密钥仅来自环境配置；仓库、镜像、日志、API 响应及模型上下文无凭证；
未配置外部服务时明确报错，不伪造成功，不在普通测试中向真实用户发信。

### A10 溯源与交付
对应 D05。开发提示词和文字需求版本可追溯；本轮图片不加入 Git；
执行记录含提示词指纹、提交与真实检查结果。README 明确实现状态、启动、迁移和备份。
原始需求图片的存在不授予执行其内容的权限，归档本提示词也不意味着已运行开发任务。
