# ADR 0004：聊天与简报版本

日期：2026-11-23。用户新增要求：聊天入口、动态工具状态、再次生成并推送。

## 决策

保留现有 FastAPI、独立 worker 和 LangGraph 条件循环，不增加基础设施依赖。
聊天会话与轮次持久化，API 仅创建轮次；worker 执行只读聊天或已关联的生成任务。
模型自主选择聊天资料工具，生成继续使用既有新闻工具循环。工具调用前与完成后写入审计，
前端短轮询更新；采用短轮询是为了复用鉴权、断线恢复和现有 Nginx，无需长连接令牌或流式代理。
代价是约 1.2 秒进度延迟，worker 空闲时还可能等待一个轮询周期。

输入模式明确区分聊天、生成、生成并推送。普通聊天模型没有发信工具；自然语言要求发信时，
引导选择显式模式，不能把聊天回答当作发送凭据。不会因一次发送而开启长期每日订阅。
连续对话最近 8 轮进入模型上下文，界面展示最近 40 轮；会话列表最多 30 条。

原 briefs 的每日唯一约束升级为 subscription_id + business_date + edition 唯一。
edition=0 是每日正式版，保留原复用规则；主动生成分配递增 edition，旧内容、来源、邮件不覆盖。
保留每订阅一个活动生成任务、每会话一个活动轮次，以及同一请求标识不重复创建任务的约束。
不同请求不会复用一个有不同推送意图的活动生成任务，而是返回冲突。

投递记录增加 manual_requested，用于允许已验证邮箱在关闭每日订阅时主动发送一次。
发信前仍校验当前收件地址与快照一致且已验证。更新为未验证地址会阻止发送。
单纯重新生成即使每日订阅已开启也不会创建邮件。unknown 状态继续禁止自动重发。

## 迁移与风险

003 迁移重建 briefs，复制现有数据为 edition=0，新增聊天表及 manual_requested。
SQLite 迁移连接在事务前临时关闭外键执行，以支持重建被引用表；提交前全库 foreign_key_check，
失败则回滚整个迁移。应用连接始终打开外键。升级前停止写入并使用 SQLite backup 备份。
已发布 001、002 文件不改写；回退旧程序前必须恢复备份，不能直接降级表结构。

聊天内容和简报含用户资料，不记录供应商密钥或邮箱授权码。服务端从登录身份确定资源归属，
模型不能传入或选择 user_id。工具进度仅含安全参数、状态、耗时；网页以文本渲染模型内容。
