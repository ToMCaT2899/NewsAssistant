# 概要设计

## 1. 目标与范围
为用户提供每日 AI 新闻简报：订阅设置 → 自主检索与核实 → 个性化筛选 → 保存 → QQ 邮箱推送。
MVP 支持多个用户的数据隔离，每个用户一个订阅，每个订阅每个业务日期一份正式简报。
用户设置的“开发者、研究人员”等身份是内容偏好，不是认证身份。
当前已落地 MVP，并完成真实模型生成、浏览器与 QQ SMTP 单次联调及用户收件确认。
用户模型设置采用个人配置门禁与加密存储；详细结果和未验收范围以 README 与开发记录为准。

MVP 功能：登录、个人模型设置、订阅编辑、聊天追问、版本化生成、每日定时、历史简报、执行状态、QQ 邮件发送。
后续再考虑公众号、企业微信、复杂角色权限、向量库、多 Agent、跨设备消息同步。

## 2. 需求与验收边界
- 自动：独立 worker 扫描到期订阅，Web 进程不承载定时任务。
- 自主：LLM 返回工具调用名称与参数；LangGraph 持续执行并回传 observation。
- 个性化：主题、包含/排除词、角色、条数、时间窗口共同进入订阅快照。
- 可信：每个事实性条目必须引用本次获取的原文或可追踪搜索结果；标记证据级别。
- 可观察：记录实际工具调用、结果摘要、错误、耗时与 token；不保存或展示隐藏思维链。
- 工程：Git、环境变量、依赖锁定、建表/迁移脚本、可复现的安装与检查。
- 五个基础工具按题目保守实现；新闻工具为额外业务能力。

## 3. 技术选择
Python 3.11+；FastAPI/Pydantic 负责接口与边界校验；LangGraph 显式状态图实现 ReAct。
SQLAlchemy 负责持久化，SQLite 负责 MVP 单机数据，后续根据并发需求迁移 PostgreSQL。
前端 Vue 3 + TypeScript + Vite，只实现必要表单、列表、详情和状态。
HTTP 客户端采用 httpx 方向，邮件可使用标准库 smtplib 与 email，阻塞 SMTP 在 worker 中运行。
依赖版本在首次安装并验证后锁定；实际运行与开发版本记录在 uv.lock，前端记录在 package-lock.json。
搜索与模型供应商通过接口替换，不依赖模型“记忆中的最新新闻”。

## 4. 模块职责
- API：认证、归属校验、输入输出模型、HTTP 错误码。
- Service：订阅、任务、简报发布、投递编排和事务边界。
- Agent：图、状态、提示词、工具注册、预算与输出校验。
- Domain：状态机、业务日期、来源引用和幂等规则。
- Repository/Models：查询与 ORM，Repository 不自行提交。
- Infrastructure：LLM、搜索、网页读取、数据库、QQ SMTP、时钟适配。
- Worker：调度到期扫描、领取生成任务、领取投递任务与故障恢复。

Docker Compose 是统一运行入口；目标部署为 frontend + api + 一个独立 worker，SQLite 使用 api/worker 共享命名卷。
两个后端进程通过短事务交互，模型和网络请求不持有数据库锁。已提供 migrate/api/worker/frontend，check/db-init 为显式工具任务，详见[运行说明](07-Docker-Compose运行说明.md)。
浏览器不直接调用模型、搜索或 SMTP，不接触供应商密钥。

## 5. 核心业务决策
- 默认 Asia/Shanghai，存储 UTC；每日生成时间按用户 IANA 时区计算。
- 在发送时间触发生成，邮件在简报完成后发送；不承诺精确分钟到达。
- 时间窗口使用半开区间 [window_start, window_end)，由任务创建时冻结。
- 同日手动触发复用已有正式简报；重试失败任务可新建 run，但不多发一封。
- 订阅变更作用于下一任务；运行中的任务使用快照。关闭订阅时取消尚未发送的投递。
- 本期没有可靠新闻时明确说明；预算耗尽属于 incomplete，默认不自动发送。
- QQ SMTP 为应用配置的统一发件箱，用户只设置收件地址，不上传个人授权码。

## 6. 可靠性与权限
单用户资源必须通过 authenticated user_id + 数据归属共同校验。
文件工具的根目录为 workspace/run_id，禁止越界、符号链接逃逸和任意 shell。
网页获取限制协议、大小、跳转和地址，阻止访问本机、内网与云元数据。
用户内容与网页均不作为系统指令；工具权限不由提示词决定。
简报与 outbox 原子保存，发送采用短事务领取；SMTP 模糊结果保留 unknown。

## 7. 实施阶段
先做 CLI 工具循环和真实来源，再接任务与数据库，再接订阅网页和 QQ 邮件。
每阶段的交付和失败场景见[实施计划](06-实施计划与验收.md)。
