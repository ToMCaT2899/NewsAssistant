# 项目结构与代码规范

## 1. 目录
以下为现有模块职责。实现状态与实际检查以 README 和开发执行记录为准，
不能把存在工具函数、适配器或离线替身视为真实外部服务端到端通过。

```text
NewsAssistant/
├── AGENTS.md
├── README.md
├── .env.example
├── compose.yaml             # 业务服务与 tools profile
├── Dockerfile               # 官方 Python 基础镜像，独立应用构建
├── .dockerignore            # 排除密钥、本地环境与数据
├── .gitignore
├── .editorconfig
├── .gitattributes
├── uv.lock                 # 运行与开发依赖锁文件
├── pyproject.toml
├── backend/
│   └── app/
│       ├── api/              # routers、schemas、auth dependencies
│       ├── service/          # subscription/run/brief/delivery 用例和事务
│       ├── domain/           # 状态机、业务日期、幂等及引用规则
│       ├── agent/
│       │   ├── graph/        # nodes、state、routing、budget
│       │   ├── tools/        # 文件、受限 shell、新闻工具及 registry
│       │   └── prompts/      # 系统提示与结构化输出规则
│       ├── repository/       # 数据访问，不自行 commit

│       └── types/
```

Compose 编排 api/worker/frontend/migrate，README 以 Compose 为主要运行入口。

## 2. Python
- 使用类型注解，公共边界定义 Pydantic/TypedDict/dataclass，不以任意 dict 贯穿系统。
- 模块与函数 snake_case，类 PascalCase，常量 UPPER_SNAKE_CASE，文件不按 utils1/2 命名。
- Ruff 负责格式与基础 lint，行宽 100；依赖实际安装后锁定并纳入 CI。
- API schema、领域对象与 ORM 分开；不在路由中写长流程、SQL 或供应商请求。
- Service/Unit of Work 负责 commit/rollback，Repository 仅 query/add/flush。
- 枚举状态统一定义；状态更新采用 expected_status 条件，失败不静默吞掉。
- 只在真实异步 I/O 链上用 async；SMTP 等阻塞代码留在 worker 或明确的线程边界。
- 禁止 eval/exec、拼接 SQL、任意 shell=True；参数化 SQL，路径与 URL 校验在执行层落实。
- 自定义异常表达业务原因，捕获具体异常并保留 cause，不使用 except: pass。
- 时间必须有时区；注入时钟便于测试；不通过本机默认时区计算用户业务日期。
- 源码注释、文档字符串和配置说明统一使用中文，保留必要的技术名词和工具指令。
- 代码注释解释约束和原因，避免逐句翻译实现。

## 3. 前端
Vue SFC 使用 script setup + TypeScript；开启 strict，公共接口不得使用 any。
请求统一经 api 客户端；模型设置仅接收用户主动输入的个人 Key，提交后清空，不写浏览器持久存储。
页面不能读取已有 Key、服务端主密钥或 SMTP 授权码；类型与后端 schema 保持一致。
表单区分保存中、成功与失败；任务区分生成失败与邮件失败。
简报 HTML 必须经过受控渲染和清理，不直接 v-html 任意模型输出。
订阅快速切换与重复点击要避免旧请求覆盖状态；禁用按钮不能替代后端幂等。
用户可读提示不暴露内部异常、密钥和完整工具参数。

## 4. 配置、日志与安全
环境变量集中校验；.env.example 只有空值或示例。真实 .env、数据、正文和日志不提交。
日志采用结构化字段，保留 request_id/run_id，不写 SMTP_AUTH_CODE、token 或密码。
认证身份与 persona 分开；所有资源查询都带数据归属条件。
工具工作区是运行隔离目录，不是项目根目录；bash 默认关闭且受限执行。
外部调用必须声明 timeout、最大响应和可重试错误，未知外部状态不得假定失败。

## 5. 检查与提交
统一检查：docker compose config --quiet、docker compose --profile tools build check、docker compose run --rm check。
check 镜像按 uv.lock 安装开发依赖，断网执行 Ruff、mypy、pytest 与文档/DDL 检查。
前端使用 ESLint + Prettier + TypeScript strict，构建镜像内执行同样的检查。
原生 Python/uv 仅用于维护调试，Git 差异检查仍在宿主机运行 git diff --check。
Dockerfile 必须排除密钥与数据，非 root 运行；发布时固定镜像版本，不挂载 Docker socket。
后端类型检查为 mypy，行为测试为 pytest；浏览器与完整 Compose 冒烟使用隔离测试资源。
仅对有实际行为的代码增加有意义测试，优先状态转换、隔离、幂等、超时和未知发送结果。
提交格式：docs: / feat: / fix: / refactor: / test: / chore: 加具体动作。
新建开发分支默认 codex/ 前缀；不强推、不改写已共享历史。
一次提交聚焦一个可审查主题；配置、SQL、接口和文档同步修改。
