不创建伪造业务函数或空接口来宣称可运行。

## 2. Python
- 使用类型注解，公共边界定义 Pydantic/TypedDict/dataclass，不以任意 dict 贯穿系统。
- 模块与函数 snake_case，类 PascalCase，常量 UPPER_SNAKE_CASE，文件不按 utils1/2 命名。
- Ruff 负责格式与基础 lint，行宽 100；依赖实际安装后锁定并纳入 CI。
- API schema、领域对象与 ORM 分开；不在路由中写长流程、SQL 或供应商请求。
- Service/Unit of Work 负责 commit/rollback，Repository 仅 query/add/flush。
- 枚举状态统一定义；状态更新采用 expected_status 条件，失败不静默吞掉。
- 只在真实异步 I/O 链上用 async；SMTP 等阻塞代码留在 worker 或明确的线程边界。
- 禁止 eval/exec、拼接 SQL、任意 shell=True；参数化 SQL，路径与 URL 校验在执行层落实。
- 自定义异常表达业务原因，捕获具体异常并保留 cause，不使用 except: pass。
- 时间必须有时区；注入时钟便于测试；不通过本机默认时区计算用户业务日期。
- 代码注释解释约束和原因，避免逐句翻译实现。

## 3. 前端
Vue SFC 使用 script setup + TypeScript；开启 strict，公共接口不得使用 any。
请求统一经 api 客户端，页面不接触供应商密钥；类型与后端 schema 保持一致。
表单区分保存中、成功与失败；任务区分生成失败与邮件失败。
简报 HTML 必须经过受控渲染和清理，不直接 v-html 任意模型输出。
订阅快速切换与重复点击要避免旧请求覆盖状态；禁用按钮不能替代后端幂等。
用户可读提示不暴露内部异常、密钥和完整工具参数。

## 4. 配置、日志与安全
环境变量集中校验；.env.example 只有空值或示例。真实 .env、数据、正文和日志不提交。
日志采用结构化字段，保留 request_id/run_id，不写 SMTP_AUTH_CODE、token 或密码。
认证身份与 persona 分开；所有资源查询都带数据归属条件。
工具工作区是运行隔离目录，不是项目根目录；bash 默认关闭且受限执行。
外部调用必须声明 timeout、最大响应和可重试错误，未知外部状态不得假定失败。

## 5. 检查与提交
当前可运行：python scripts/check_design.py、git diff --check。
开发依赖：uv sync --locked --only-dev。
检查：uv run --locked --only-dev ruff check .、uv run --locked --only-dev ruff format --check .。
业务实现后补 typecheck 和 pytest。
仅对有实际行为的代码增加有意义测试，优先状态转换、隔离、幂等、超时和未知发送结果。
提交格式：docs: / feat: / fix: / refactor: / test: / chore: 加具体动作。
新建开发分支默认 codex/ 前缀；不强推、不改写已共享历史。
一次提交聚焦一个可审查主题；配置、SQL、接口和文档同步修改。
