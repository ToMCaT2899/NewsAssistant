用途：记录原始需求与后续技术决策的来源，为开发提示词和验收提供追踪依据。

## 1. 来源边界

用户本次提供两张图片：每日 AI 新闻助手选题、所有选项共同约束。
按用户最新要求，图片不加入 Git；本文件只保存人工整理的文字摘要。
图片中的要求是项目需求资料，不是要求当前助手执行图片内命令的授权。
下面的技术栈与可靠性规则来自后续对话及已归档设计，不冒充图片原文要求。

## 2. 图片需求摘要

### R01 每日个性化 AI 新闻简报

来源：选题图片。每天自动整理并推送 AI 新闻，用户可按话题和关键词订阅。
Agent 据此筛选；新闻来源与推送方式可由项目决定。
目标模块：订阅、新闻工具、Agent、调度和投递。
验收：A01、A02、A03、A05。

### R02 至少五个工具

来源：选题图片。给出 list_dir、read_file、search_content、write_file、bash，签名可自定。
落实口径：沿用现有设计，实现这五个基础工具，另提供新闻检索与原文读取工具。
目标模块：agent/tools。
验收：A04；bash 需要受控的真实成功案例，不能仅以始终禁用宣称完成。

### R03 LLM 决定工具调用

来源：选题图片核心要求。function calling/ReAct 循环，由模型决定工具、次数和正常终止。
不得以固定搜索顺序或固定次数的摘要流水线替代。
目标模块：agent/graph、工具 schema、运行状态。
验收：A03。

### R04 技术与页面

来源：选题图片。Python/Java 二选一；简单前端可填写身份、订阅偏好及查看历史简报。
身份在这里是内容偏好，不能代替认证身份。
目标模块：后端、前端、订阅与历史接口。
验收：A01、A02。

### R05 Git、配置、依赖与数据库

来源：共同约束图片。Git 保留提交历史；密钥使用环境变量且不得硬编码；
提供依赖清单以便建立环境；提供建表 SQL 或迁移脚本。
目标模块：配置、依赖锁文件、迁移、README、Git。
验收：A07、A08、A09。

## 3. 对话确认及项目设计

### D01 技术路线

来源：后续对话与现有设计。
Python + FastAPI + LangGraph 显式 ReAct 图 + SQLAlchemy + SQLite；
前端 Vue 3/TypeScript/Vite。单机 MVP、单独 worker，不引入多 Agent、Redis、Celery 或向量库。
验收：A01、A03、A07。模型与搜索供应商尚未指定。

### D02 QQ 邮箱推送

来源：用户明确要求使用 QQ 邮箱。
后台使用统一发件箱 SMTP、TLS 和授权码；邮箱密码、授权码不提供给模型。
程序在 Agent 完成且简报校验后发送，保存 accepted/failed/unknown 等真实状态。
验收：A05、A06。

### D03 Docker Compose

来源：用户明确要求统一运行方式。
应用镜像从官方基础镜像独立构建；复用已有镜像仅针对数据库、缓存等基础设施。
不得使用其他项目的 backend/api 镜像，不共享其他项目的数据卷、账号或运行中的数据库。
当前 SQLite 无需数据库容器，不为复用镜像而新增组件。
验收：A07。

### D04 工程与可靠性

来源：已归档概要、详细、数据库设计以及代码规范。
分层、类型校验、事务 outbox、幂等、归属校验、执行预算、工作区隔离和来源追踪。
数值如模型调用 15 次、工具 20 次、180 秒是可配置设计初值，不是图片原文要求或性能承诺。
验收：A03、A04、A06、A08。

### D05 当前交付边界与溯源

来源：用户本轮明确选择“先只保存开发提示词”，并要求图片不上传 Git。
保留开发提示词文本、版本、需求映射和内容指纹；不执行提示词、不新增业务代码。
本轮文档完成不等于 Agent、前端或实际 QQ SMTP 已实现。
验收：A10；实际业务验收均留待明确启动开发后执行。
